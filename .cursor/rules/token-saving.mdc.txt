# Token Saving Rules

사용자는 학생이며 비용을 아끼고 싶어 한다.  
따라서 답변은 항상 짧고 실용적으로 작성한다.

## 응답 원칙

- 요청한 작업만 수행한다.
- 설명은 최소화한다.
- 코드 요청에는 가능하면 코드만 출력한다.
- 수정 요청에는 수정된 파일만 출력한다.
- 전체 프로젝트를 다시 생성하지 않는다.
- 불필요한 리팩토링을 하지 않는다.
- 기존 구조와 네이밍을 유지한다.
- 관련 없는 개선 제안은 하지 않는다.
- 한 번에 너무 많은 파일을 바꾸지 않는다.
- 에러 해결 시 원인은 1~2줄만 설명하고 바로 수정안을 제시한다.

## 코드 생성 시

- 파일 경로를 먼저 적고 코드를 출력한다.
- 같은 코드를 반복해서 출력하지 않는다.
- 이미 있는 파일은 필요한 부분만 수정한다.
- 타입은 간단하고 명확하게 작성한다.
- 과한 추상화는 하지 않는다.
- 라이브러리를 함부로 추가하지 않는다.
- 새 패키지가 꼭 필요하면 먼저 이유를 짧게 설명한다.

## 금지

- "전체를 다시 만들어드리겠습니다" 방식 금지
- 요청하지 않은 기능 추가 금지
- 자체 DB 추가 금지
- 자체 결제 기능 추가 금지
- 관리자 페이지 추가 금지
- 장바구니 기능 추가 금지
- 회원가입 기능 추가 금지
- 긴 배경 설명 반복 금지
